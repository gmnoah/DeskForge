# DeskForge 功能兼容重建规格

日期：2026-10-06。目标：未来版本保持当前产品能力，业务实现从本规格重新开发。当前桌面程序继续作为过渡版。

## 产品约定

服务使用 macOS 的中文用户：在明确授权的本地工作区内整理资料、生成文档、处理代码任务，连接用户选择的模型与工具。默认本地保存资料和会话；涉及模型、向量服务、联网工具的外发必须明确说明。

“功能相同”指用户能完成相同任务，权限边界与数据保护不降低；不要求内部类型、数据库表、文件组织、样式或提示词相同。重新设计的界面也要保留可发现的操作入口。

## 必须覆盖的能力

详见 ACCEPTANCE.md 的 F01–F30。前期纵向交付只是实施顺序，不能据此从最终版本删减功能。README 描述的能力、模块名称提示的能力、实际运行证据分别记录；只有实际验收才能确认行为兼容。

## 两个独立选择

- 执行方式：直接执行；先提供计划，由用户确认后执行。计划阶段只允许只读工具。
- 确认方式：请求批准；工作区内自动处理。自动处理仅适用于受信任的执行器能够回滚的本地文件操作。命令执行需要额外校验，不因命令名为 test/build 就推断无外发或可撤销。

原版的验证命令自动处理需求保留为独立待验收能力；新内核暂不提供命令自动批准。扩展时必须说明项目脚本、生命周期钩子、子进程与网络权限的处理办法。

## 首批交付

先实现可测试的任务与审批内核，再实现工作区文件执行器、模型请求、会话存储和桌面入口。内核不得直接读文件、启动命令或持有模型密钥；这些能力由受信任的宿主注册和执行。

## 发行完成条件

所有功能有验收记录；数据迁移可回退；新目录不依赖旧业务模块；源代码、文本、资源、依赖和发行包经过来源审查。当前实现人员已接触旧源码，不声称严格净室开发。独立目录、新 Git 历史和测试通过都不能单独证明版权独立。
