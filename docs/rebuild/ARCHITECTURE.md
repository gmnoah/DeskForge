# 独立实现架构

## 边界

1. 桌面宿主：窗口、系统选择器、安全密钥存储与更新。渲染层只能访问受限的产品接口。
2. 任务内核：执行方式、工具请求队列、批准/拒绝、取消、错误与状态快照。第一版仅驻留内存。
3. 能力注册表：宿主按工具注册风险、权限检查与执行函数；模型不能自报风险等级。修改注册表必须经宿主重建任务或显式版本切换。
4. 文件执行器：真实路径解析、符号链接与越界检查、敏感文件规则、文件版本和回滚。执行前重新检查，拒绝审批后内容变更。宿主负责避免路径检查与执行之间的竞态。
5. 模型适配器：按公开协议连接、流解析、工具请求、用量、脱敏与取消。只提交经授权的上下文。
6. 数据服务：自己的版本化存储格式；会话、知识、审计分别保存。导入器只解析有文档的交换格式。
7. 扩展宿主：MCP、Skill、浏览器、自动化；按独立能力注册接入权限核心。

## 第一版内核协议

任务提供 ID、执行方式 direct/plan、确认方式 ask/workspace-auto。状态为 planning、ready、waiting、executing、completed、failed、cancelled。计划确认是宿主动作。

工具请求包含工具名和 JSON 参数。宿主注册 access=read/write/rollback-write/command/external/destructive 与 validate、execute 函数。validate 在申请和实际执行前都调用，负责工作区、敏感数据与外发检查；参数冻结后传入。任何未知工具或检查失败都禁止执行。

read 可执行；rollback-write 在 workspace-auto 下可执行；其它请求需要一次性批准。计划阶段拒绝非 read 请求。每个申请生成独立随机票据，批准仅绑定该票据中的冻结参数；不会产生相同参数、会话或永久授权。这些兼容能力在后续阶段单独添加并验收。

同一任务串行执行；执行中拒绝新申请，避免并发副作用。取消向执行器传递 AbortSignal；取消后的晚到结果不得恢复任务或登记成功。执行器必须自己实现取消和清理，内核不能撤销已经发生的副作用。

## 信任与审计

此内核是宿主库，不是防恶意宿主的进程沙箱。UI 与模型不得直接取得 approve/confirmPlan/register 权限。需要审批身份校验的 IPC 在宿主层实现。

记录包含单调序号、事件类型和申请 ID，不记录参数与工具结果，减少秘密进入日志的机会。持久化、哈希链、恢复与跨进程授权尚未实现。重启时禁止自动重放待执行副作用。

## 开发隔离

新实现位于 independent/，使用自己的 package.json，无旧业务依赖、无源码复制、无共用配置。这里只临时共处一个仓库；最终迁出并建立独立历史。审核工具可比较旧文件的摘要，但新运行时禁止导入 apps/desktop、packages/core 或 packages/contracts。

## 来自旧版演进的核心约束与架构防线 (M1–M5, S7, P1–P4)

### 1. 数据层架构与迁移 (M1, M2, P1, P2, P3)
- **迁移体系**：严禁通过运行时 `PRAGMA table_info` 动态检测列的存在性进行临时打补丁。必须使用标准 SQLite `PRAGMA user_version` 与单调递增的编号迁移函数序列，各版本必须具备完备的单元升级与幂等性测试。
- **仓储领域化拆分**：严格禁止单一超大文件数据层（如旧版 `database.ts` 超过 1500 行混杂所有领域）。数据层按领域拆分为 Runs、Messages、Approvals、Audit、Knowledge 各子仓储；IPC 处理层只做参数解析与数据转换。
- **列表下推与分页投影**：`runs:list` 等高频列表查询仅返回摘要投影（RunSummary，耗时保持在毫秒级），禁止深度关联与反序列化全量消息；历史消息支持从数据库按时间倒序分页（默认 200 条），防止大体积会话卡顿。
- **轻量事件通知**：主进程状态事件（如 `run.updated`）只广播必要状态增量或轻量摘要（< 1 KB），禁止将完整会话图谱全量推入 IPC。
- **全外键与查询索引**：所有关联查询（如 `artifacts`、`approvals`、`task_steps`）必须显式建立组合索引。

### 2. 渲染层架构与性能 (M3, P4, P6)
- **严格共享类型定义**：渲染层必须直接复用 Contracts 契约库定义的单一数据源类型，禁止在前端重新声明冗余类型定义（M3），消除数十个临时转换函数带来的脆弱性。
- **流式增量与时间线解耦**：流式输出采用独立的瞬时状态与帧缓冲（`requestAnimationFrame`）批量聚合，禁止在每个流式 delta 到达时重新构建整条任务事件时间线。
- **渲染组件记忆化**：Markdown 渲染器（`MemoMarkdown`）与历史轮次行必须完全基于 ID 和内容变化记忆化（`React.memo`），保证长流式过程中历史轮次重渲染次数为 0。
- **非核心视图按需分割**：次级视图、设置面板、文档预览弹窗等全部走代码分割（`React.lazy` + `Suspense`），保持渲染层首屏核心 JS Bundle 控制在 700 KB 以下。

### 3. 安全基线与隔离沙箱 (S1–S7)
- **API Key 零透传**：模型 API Key 与凭据严格限定在主进程安全存储层，禁止下发至渲染层或 Worker，日志与快照导出前必须强制脱敏。
- **Shell 执行隔离**：命令执行强制采用非登录 Shell（`-c`），启动时缓存系统 PATH，彻底屏蔽环境文件注入（`ENV` / `BASH_ENV` / `ZDOTDIR`），并对复合子 Shell 与别名绕过实施递归阻断。
- **调用上限与绝对超时**：所有跨进程和网络外部调用（MCP 工具、HTTP 请求、子进程执行）必须显式配置超时硬限制，禁止由于外部服务挂起导致任务无限停滞。
- **隔离预览沙箱**：HTML、SVG、富文本及 Office 文档预览必须在独立沙箱 iframe 中运行，严禁配置 `allow-same-origin`，阻断对宿主 API 与敏感上下文的访问。
- **进程树监控与孤儿回收**：监听 Worker utilityProcess 崩溃事件（`child-process-gone`），在崩溃时自动安全暂停任务并递归回收全部关联子进程树。
