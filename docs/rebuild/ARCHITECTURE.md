# 独立实现架构

## 边界

1. 桌面宿主：窗口、系统选择器、安全密钥存储与更新。渲染层只能访问受限的产品接口。
2. 任务内核：执行方式、工具请求队列、批准/拒绝、取消、错误与状态快照。第一版仅驻留内存。
3. 能力注册表：宿主按工具注册风险、权限检查与执行函数；模型不能自报风险等级。修改注册表必须经宿主重建任务或显式版本切换。
4. 文件执行器：真实路径解析、符号链接与越界检查、敏感文件规则、文件版本和回滚。执行前重新检查，拒绝审批后内容变更。宿主负责避免路径检查与执行之间的竞态。
5. 模型适配器：按公开协议连接、流解析、工具请求、用量、脱敏与取消。只提交经授权的上下文。
6. 数据服务：自己的版本化存储格式；会话、知识、审计分别保存。导入器只解析有文档的交换格式。
7. 扩展宿主：MCP、Skill、浏览器、自动化；按独立能力注册接入权限核心。

## 第一版内核协议

任务提供 ID、执行方式 direct/plan、确认方式 ask/workspace-auto。状态为 planning、ready、waiting、executing、completed、failed、cancelled。计划确认是宿主动作。

工具请求包含工具名和 JSON 参数。宿主注册 access=read/write/rollback-write/command/external/destructive 与 validate、execute 函数。validate 在申请和实际执行前都调用，负责工作区、敏感数据与外发检查；参数冻结后传入。任何未知工具或检查失败都禁止执行。

read 可执行；rollback-write 在 workspace-auto 下可执行；其它请求需要一次性批准。计划阶段拒绝非 read 请求。每个申请生成独立随机票据，批准仅绑定该票据中的冻结参数；不会产生相同参数、会话或永久授权。这些兼容能力在后续阶段单独添加并验收。

同一任务串行执行；执行中拒绝新申请，避免并发副作用。取消向执行器传递 AbortSignal；取消后的晚到结果不得恢复任务或登记成功。执行器必须自己实现取消和清理，内核不能撤销已经发生的副作用。

## 信任与审计

此内核是宿主库，不是防恶意宿主的进程沙箱。UI 与模型不得直接取得 approve/confirmPlan/register 权限。需要审批身份校验的 IPC 在宿主层实现。

记录包含单调序号、事件类型和申请 ID，不记录参数与工具结果，减少秘密进入日志的机会。持久化、哈希链、恢复与跨进程授权尚未实现。重启时禁止自动重放待执行副作用。

## 开发隔离

新实现位于 independent/，使用自己的 package.json，无旧业务依赖、无源码复制、无共用配置。这里只临时共处一个仓库；最终迁出并建立独立历史。审核工具可比较旧文件的摘要，但新运行时禁止导入 apps/desktop、packages/core 或 packages/contracts。
